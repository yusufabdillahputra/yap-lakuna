# F2-01 Server sync & aktivasi hosting — Rencana implementasi

> **Untuk agen:** SUB-SKILL WAJIB: superpowers:subagent-driven-development
> (disarankan) atau superpowers:executing-plans, tugas demi tugas. Langkah
> memakai kotak centang (`- [ ]`).

**Tujuan:** perangkat Lakuna bisa diaktifkan ke server Serverpod di VPS,
mengunggah semua data dan gambar, lalu tersinkron dua arah dengan perangkat
lain tanpa pernah menahan kasir.

**Arsitektur:** outbox per baris yang sudah ada didorong ke endpoint `sync.push`
(LWW per baris dengan HLC, transisi dokumen final monoton, savepoint per
entri) dan perubahan ditarik lewat `sync.pull` dari log `sync_changes`
berurutan. Mesin sync klien (`SyncEngine`) hidup di `lakuna_data` di balik
`SyncTransport` abstrak. Aktivasi memakai kode aktivasi dari admin server dan
akun pemilik (auth email Serverpod), perangkat berikutnya memakai kode pasang.

**Tech stack:** Dart 3.13, Flutter 3.47.9, Serverpod 4.1 (Postgres di
server, SQLite di perangkat), Forui, `serverpod_cloud_storage_s3_compat`,
Docker Compose + Caddy.

**Spec:** `docs/superpowers/specs/2026-11-27-f2-01-server-sync-design.md`
(nomor aturan di bawah merujuk spec ini).

## Batasan global

- Ikuti `CLAUDE.md`: TDD, `dart format`, `dart analyze --fatal-infos` /
  `flutter analyze --fatal-infos`, semua tes, review subagent, uji Xvfb.
- Model `.spy.yaml`, `serverpod generate`, migrasi
  `serverpod create-migration --tag <tag>`; kode generate di-commit.
- Field multi-kata wajib `column=snake_name`; tabel jamak snake_case.
- Semua tulis data bisnis di perangkat tetap lewat `SyncTx`; baris dari
  pull ditulis **tanpa** outbox (aturan 2).
- Uang `int` rupiah, jumlah `int` mili-satuan; tanpa `double`.
- Setiap kunci l10n baru ada di `app_id.arb` dan `app_en.arb`.
- Tiap tahap = satu rilis (`version:` pubspec naik, CHANGELOG Bahasa
  Indonesia dengan bagian Ditambahkan/Diubah/Diperbaiki/Catatan teknis,
  STATUS-JEDA dan tabel Status & gap spec diperbarui), PR ke `main`,
  squash-merge setelah CI hijau.
- Batch push maks 500 entri atau 1 MB; `maxRequestSize` 4194304; pull maks
  1.000 per halaman; HLC masa depan > 5 menit ditolak; kode pasang 8
  karakter, 15 menit; token perangkat 256 bit, server menyimpan hash.

## Fokus review

1. Batch berisi induk yang ditolak lalu anak-anaknya: anak harus
   `rejected/dependency`, batch lain tetap `applied` (tes di Tugas 3).
2. Void di perangkat B dan retur sebagian di perangkat A untuk nota yang
   sama, urutan tiba dibalik: hasil akhir tetap `voided` di server dan
   kedua perangkat (Tugas 3 dan Tugas 8).
3. Aplikasi ditutup di tengah pemadatan outbox lalu dibuka lagi: tidak ada
   baris terlewat atau ganda di outbox (Tugas 6).
4. Pull membawa baris yang FK-nya belum ada di perangkat: diparkir lalu
   berhasil di siklus berikutnya, kursor tidak macet (Tugas 7).
5. Perangkat dari salinan backup mencoba aktivasi/pasang dengan ID
   perangkat yang sudah punya token: ditolak dengan pesan salinan
   (Tugas 5 dan Tugas 9).

### Tugas 3: Penerap perubahan di server

**Berkas:**
- Buat: `lakuna_server/lib/src/sync/apply_change.dart`
- Tes: `lakuna_server/test/integration/sync_apply_test.dart`

**Antarmuka:**
- Konsumsi: `syncTables`, `mergeSaleStatus`, `mergePurchaseStatus` (Tugas 1);
  model Tugas 2.
- Hasil: `class DeviceAuth { final UuidValue tenantId; final UuidValue deviceId; }`
  dan
  `Future<SyncPushResult> applyPushEntry(Session session, Transaction tx, DeviceAuth auth, SyncPushEntry entry, {required DateTime serverNow})`.
  Setiap entri dijalankan dalam savepoint (`tx.createSavepoint()`); galat
  Postgres FK → `rejected/dependency`, unik → `rejected/unique` (kecuali
  `settings` → `merged`, aturan 8b). Penulisan baris generik: ubah payload
  (kunci nama field Dart) ke nama kolom lewat `TableDefinition.columns`
  (`dartName` → `name`) lalu
  `INSERT ... SELECT * FROM jsonb_populate_record(NULL::"<tabel>", $1) ON CONFLICT (id) DO UPDATE ...`.
  Baris yang diterapkan juga disisipkan ke `sync_changes`
  (`outlet_id` dari payload bila ada).

- [ ] Tes gagal (satu `test` per butir, Postgres tertanam via
  `withServerpod`):
  - baris baru → `applied`, ada di tabel dan `sync_changes`;
  - kirim ulang `(rowId, hlc)` sama → `applied`, `sync_changes` tidak bertambah;
  - HLC lebih lama dari baris server → `stale` dengan `serverPayloadJson`;
  - `tenant_id` asing → `rejected/tenant`; `originDeviceId` ≠ perangkat
    token → `rejected/device`; tabel tak dikenal / tabel client →
    `rejected/table`; HLC > `serverNow` + 5 menit → `rejected/clock`;
  - nota `completed` diubah totalnya → `rejected/final` dan satu baris
    `sync_conflicts`;
  - nota `partiallyReturned` (HLC lebih baru) tiba setelah `voided` →
    `merged`, status tetap `voided`; urutan dibalik juga `voided`;
  - `settings` kunci sama ID beda → `merged`, satu baris tersisa;
  - batch berisi outlet baru yang ditolak (kode outlet bentrok) lalu
    `stock_locations` anaknya: anak `rejected/dependency`, entri lain di
    batch yang sama `applied` (Fokus review 1);
  - payload tanpa kolom baru (mis. `discountBase`) → kolom `null`.
- [ ] Jalankan `cd lakuna_server && dart test test/integration/sync_apply_test.dart`: gagal.
- [ ] Implementasi `applyPushEntry`.
- [ ] Jalankan lagi: lulus. Commit.
